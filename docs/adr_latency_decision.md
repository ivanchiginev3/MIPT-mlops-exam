# ADR-001: Выбор архитектуры на основе Metrics Driven Development

## Статус

Принято

## Дата

31.05.2026

## Контекст

В рамках проектирования ML-системы для предсказания оттока клиентов необходимо выбрать архитектурное решение для production-сервиса.

Для принятия решения были предоставлены результаты измерений времени отклика двух реализаций системы:

* Архитектура A — существующая система.
* Архитектура B — улучшенная система.

Были собраны выборки времени ответа (latency) для каждой реализации.

Среднее время ответа:

* Архитектура A: около 3.5 секунд.
* Архитектура B: около 2.0 секунд.

## Проблема

Необходимо определить, является ли наблюдаемое снижение времени ответа статистически значимым и следует ли переводить пользователей на новую архитектуру.

## Гипотезы

### H0

Среднее время отклика двух систем одинаково.

### H1

Среднее время отклика улучшенной системы меньше, чем у существующей.

## Метод анализа

Для сравнения независимых выборок используется двухвыборочный t-тест Уэлча (Welch's t-test).

Причины выбора:

* выборки независимы;
* размеры выборок велики;
* дисперсии могут различаться.

Уровень значимости:

```text
α = 0.05
```

## Результаты

По визуальному анализу распределений видно значительное смещение времени отклика в сторону меньших значений для новой архитектуры.

Проведенный статистический анализ показывает:

```text
p-value < 0.05
```

Следовательно, нулевая гипотеза H0 отвергается.

Различия между системами являются статистически значимыми.

## Решение

Принять архитектуру B в качестве основной производственной архитектуры.

Переключить пользовательский трафик на новую систему.

## Последствия

### Положительные

* снижение среднего времени ответа;
* улучшение пользовательского опыта;
* повышение производительности сервиса;
* снижение нагрузки на инфраструктуру.

### Риски

* необходимость контроля после развертывания;
* возможное изменение характеристик под реальной нагрузкой;
* необходимость мониторинга latency и error rate.

## Контроль результата

После внедрения отслеживаются следующие SLI:

* API Latency;
* API Availability;
* Error Rate.

Если после внедрения наблюдается ухудшение технических показателей, возможен откат на предыдущую версию системы.
