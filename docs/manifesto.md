# ML-манифест проекта

# 1. Проект

**ML-система прогнозирования оттока клиентов банка**

---

# 2. Предпосылки проекта

Банки регулярно сталкиваются с проблемой оттока клиентов. Потеря клиента приводит к снижению выручки и увеличению затрат на привлечение новых пользователей.

Для решения данной проблемы требуется система, способная заранее выявлять клиентов с высоким риском ухода и предоставлять результаты анализа бизнес-подразделениям для принятия решений по удержанию клиентов.

---

# 3. Ценностное предложение

Разрабатываемая система позволяет:

* выявлять клиентов с высоким риском оттока;
* повышать показатель удержания клиентов (Retention Rate);
* снижать потери клиентской базы;
* эффективнее использовать маркетинговый бюджет;
* принимать решения на основе данных;
* автоматизировать процесс оценки риска оттока.

---

# 4. Цели проекта

Основные цели проекта:

1. Построить модель бинарной классификации для прогнозирования оттока клиентов.
2. Реализовать воспроизводимый пайплайн подготовки данных и обучения модели.
3. Настроить трекинг экспериментов и версионирование моделей.
4. Развернуть API-сервис для инференса модели.
5. Реализовать мониторинг технических, модельных и бизнес-метрик.
6. Реализовать управление жизненным циклом модели и безопасное обновление Production-версии.

---

# 5. Описание решения

Система решает задачу бинарной классификации.

На вход подаются характеристики клиента:

* CreditScore;
* Geography;
* Gender;
* Age;
* Tenure;
* Balance;
* NumOfProducts;
* HasCrCard;
* IsActiveMember;
* EstimatedSalary.

На выходе система возвращает:

* вероятность оттока;
* бинарный прогноз;
* версию используемой модели.

---

# 6. Архитектура системы

В состав системы входят:

* модуль подготовки данных;
* модуль обучения моделей;
* механизм выбора лучшей модели;
* MLflow для трекинга экспериментов;
* жизненный цикл Candidate → Production;
* FastAPI для инференса;
* Docker для контейнеризации;
* GitHub Actions для CI;
* система мониторинга на основе SLI/SLO;
* облачное развертывание в Yandex Cloud.

Заявленный уровень зрелости ML-системы: **Уровень 2**.

---

# 7. Данные

Для обучения используется открытый датасет Customer Churn Dataset.

Целевая переменная:

* Exited = 1 — клиент ушёл;
* Exited = 0 — клиент остался.

Источник обучающих данных:

* исторические данные о клиентах банка.

Источник продовых данных:

* данные, поступающие через REST API.

---

# 8. Выбор модели

В процессе обучения система обучает несколько моделей-кандидатов:

* Random Forest;
* XGBoost.

Для каждой модели рассчитываются следующие метрики:

* ROC-AUC;
* Precision;
* Recall;
* F1-score.

После обучения модели сравниваются между собой.

Лучшая модель по метрике F1-score сохраняется как Candidate-модель.

---

# 9. Жизненный цикл модели

Система реализует следующий жизненный цикл:

Данные

↓

Обучение моделей

↓

Выбор лучшей модели

↓

Candidate Model

↓

Проверка SLO

↓

Сравнение с Production Model

↓

Promote / Reject

↓

Production Model

↓

Archive Previous Version

Новая модель переводится в Production только в случае выполнения требований SLO и улучшения качества относительно текущей Production-модели.

Предыдущая Production-модель сохраняется в архиве для возможности отката.

---

# 10. Метрики качества

## Бизнес-метрики

* Retention Rate;
* Churn Rate;
* снижение количества ушедших клиентов.

## ML-метрики

* ROC-AUC;
* Precision;
* Recall;
* F1-score.

Для данной задачи особое значение имеет Recall, так как важно не пропустить клиентов с высоким риском ухода.

---

# 11. SLI и SLO

## Технические SLI

* Latency;
* Availability;
* Error Rate;
* CPU Usage;
* Memory Usage.

## Модельные SLI

* ROC-AUC;
* Precision;
* Recall;
* F1-score;
* Data Drift;
* Prediction Drift.

## Бизнесовые SLI

* Retention Rate;
* Churn Rate.

Минимальные требования для публикации модели:

* ROC-AUC ≥ 0.85;
* Precision ≥ 0.60;
* Recall ≥ 0.60;
* F1-score ≥ 0.60.

---

# 12. Инференс

Для предоставления прогнозов используется REST API.

Основные endpoints:

* GET /health
* POST /predict

Endpoint `/health` используется для проверки доступности сервиса.

Endpoint `/predict` принимает признаки клиента и возвращает прогноз вероятности оттока.

---

# 13. Metrics Driven Development

Проект использует подход Metrics Driven Development.

Архитектурные решения принимаются на основе анализа метрик системы и статистических тестов.

Результаты анализа оформляются в виде ADR-документов.
