# ADR-001: Принятие решения на основе Metrics Driven Development

## Статус

Принято

## Контекст

В ходе проектирования ML-системы рассматривались две архитектуры сервиса предсказания оттока клиентов.

Архитектура A — существующая реализация.

Архитектура B — улучшенная реализация.

Для оценки эффективности использовалась метрика latency (время отклика сервиса).

Были предоставлены два массива измерений времени отклика.

Среднее время отклика:

* Существующая система: около 3.5 секунд
* Улучшенная система: около 2.0 секунд

## Гипотезы

Нулевая гипотеза H0:

Среднее время отклика обеих систем одинаково.

Альтернативная гипотеза H1:

Улучшенная система имеет меньшее среднее время отклика.

## Метод анализа

Для проверки статистической значимости использовался двухвыборочный t-тест Уэлча (Welch t-test).

Уровень значимости:

α = 0.05

## Результаты

Анализ распределений показывает заметное снижение времени отклика в улучшенной системе.

Полученное значение p-value значительно меньше 0.05.

Следовательно, нулевая гипотеза H0 отвергается.

Статистически подтверждается, что улучшенная система работает быстрее.

## Решение

Принять архитектуру B в качестве основной производственной архитектуры.

Развернуть новую версию сервиса и переключить пользовательский трафик на нее.

## Последствия

Положительные:

* уменьшение времени ответа;
* повышение качества пользовательского опыта;
* снижение нагрузки на инфраструктуру.

Риски:

* необходимость дополнительного мониторинга после развертывания;
* возможное изменение поведения системы под реальной нагрузкой.

Для контроля используются технические SLI/SLO метрики latency и error rate.
